# 모션 저작 절차

## 왜 이 절차가 필요한가

밋밋한 모션은 대부분 **동작을 한 덩어리로 만들어서** 생긴다. A에서 B로 옮기고 끝내면
뇌가 "물체가 이동했다"로만 읽는다. 사람이 "쫀득하다 / 묵직하다 / 시원하다"고 느끼는 건
**동작 전후에 붙은 것들** — 준비 자세, 목표를 지나쳤다 돌아오는 반동, 잦아드는 여운 — 이다.

그래서 순서가 중요하다. **어디로 움직일지가 아니라, 언제 무엇을 하는지를 먼저 정한다.**

---

## 1단계 — 동작을 3막으로 쪼갠다

무슨 동작이든 먼저 이 표를 채운다. 채우지 않고 키를 찍기 시작하면 반드시 밋밋해진다.

| 막 | 하는 일 | 방향 |
|---|---|---|
| **① 예비** (웅크림) | 힘을 모은다 | **가려는 방향의 반대로** |
| **② 본동작** | 실제로 일어나는 일 | 목표 방향으로, 목표를 **지나쳐서** |
| **③ 여운** | 지나친 만큼 되돌아와 잦아든다 | 되돌아옴 |

**핵심은 ①의 방향이 반대라는 것이다.** 던지려면 먼저 뒤로 젖히고, 뛰려면 먼저 웅크리고,
때리려면 먼저 당긴다. 이게 없으면 동작이 "갑자기 시작"돼서 뚝 끊겨 보인다.

**시간 배분** (전체 T를 100%로):

| 막 | 비율 | 이유 |
|---|---|---|
| ① 예비 | **30~40%** | 길수록 무겁고 강해 보인다. 짧으면 잽싸다 |
| ② 본동작 | **10~20%** | **가장 짧아야 한다.** 이게 길면 느려 보인다 |
| ③ 여운 | **40~50%** | 여기가 짧으면 뚝 끊긴다 |

초보자가 가장 많이 하는 실수는 **본동작을 길게, 여운을 짧게** 잡는 것이다. 정반대로 해야 한다.
"빠르다"는 느낌은 본동작의 절대 속도가 아니라 **예비와의 대비**에서 나온다.

**무게에 따라 비율을 조절한다:**
- 가벼움·잽쌈 (칼, 물기) → 예비 25% / 본동작 20% / 여운 55%
- 묵직함 (도끼, 내려찍기, 큰 펫) → 예비 45% / 본동작 10% / 여운 45%

---

## 2단계 — 키프레임을 어디에 찍나

막의 경계에만 찍는다. **중간을 채우려 하지 마라** — 그건 이징이 할 일이다.
키가 많을수록 좋아지지 않는다. 오히려 곡선이 울퉁불퉁해진다.

**표준 5키** (거의 모든 동작이 이걸로 된다):

```
K0 ────── K1 ─── K2 ── K3 ────── K4
시작      예비    오버   되돌아옴   정지
          정점    슈트
0%       35%    50%    65%      100%
```

| 키 | 값 | 설명 |
|---|---|---|
| **K0** | 원래 자세 | 시작 |
| **K1** | **반대 방향 최대** | 예비 정점. 여기서 살짝 머문다 |
| **K2** | **목표를 지나친 값** | 본동작 도착. 목표의 **1.1~1.3배** |
| **K3** | 목표를 살짝 못 미친 값 | 되돌아오며 반대로 튐. 목표의 **0.95배** |
| **K4** | 목표 자세 | 정지 |

**K2의 오버슈트가 임팩트의 정체다.** 목표에 정확히 도착하면 밋밋하다. 지나쳤다가
돌아와야 "힘이 실렸다"고 읽힌다. K3의 미세한 반대 튐까지 있으면 훨씬 살아난다.

**오버슈트를 넣으면 안 되는 것:** 발이 땅에 닿는 순간, 무기가 벽에 박히는 순간처럼
**물리적으로 더 갈 수 없는 곳**. 여기선 대신 **스쿼시**(눌림)로 충격을 표현한다.

---

## 3단계 — 구간마다 이징을 정한다

키 사이를 **어떻게** 이동하는지가 실제 느낌을 만든다. 각 구간의 성격이 다르다.

| 구간 | 이징 | 왜 |
|---|---|---|
| K0 → K1 (예비) | **Ease Out** (빨리 갔다 천천히 멈춤) | 힘을 모으고 정점에서 뜸을 들인다 |
| K1 → K2 (본동작) | **Ease In** (천천히 시작해 폭발) | 정점에서 터져 나가는 느낌 |
| K2 → K3 (반동) | **Ease Out** (빠르게 갔다 감속) | 튕겨 돌아옴 |
| K3 → K4 (정착) | **Ease In-Out** (아주 부드럽게) | 스르륵 잦아듦 |

**가장 흔한 실수는 전 구간 Linear(등속)** 다. 등속은 기계가 움직이는 것처럼 보인다.
살아있는 것은 절대 등속으로 움직이지 않는다.

### Unity 애니메이션 창에서 (클립 저작)

키를 우클릭 → 탄젠트를 지정한다.

| 원하는 것 | 탄젠트 설정 |
|---|---|
| Ease Out (도착하며 감속) | 도착 키의 **In 탄젠트 = Flat** |
| Ease In (출발하며 가속) | 출발 키의 **Out 탄젠트 = Flat** |
| 정점에서 뜸 들이기 | 그 키의 **양쪽 다 Flat** |
| 급격한 전환 (충격) | **Broken** 으로 쪼개고 양쪽을 다르게 |
| 등속 | Linear — **거의 쓸 일이 없다** |

기본값(Clamped Auto)은 무난하지만 밋밋하다. **최소한 K1(예비 정점)과 K2(오버슈트)는
직접 지정해라.** 그 둘만 만져도 확 달라진다.

### 코드에서 (절차 모션)

`k` 는 0→1 진행도(`t / duration`). 이 함수들을 쓴다:

```csharp
float easeIn    = k * k;                       // 천천히 → 폭발  (본동작)
float easeOut   = 1f - (1f - k) * (1f - k);    // 빠르게 → 감속  (예비·반동)
float smooth    = k * k * (3f - 2f * k);       // 가속-감속 S곡선 (정착·이동)
float arc       = Mathf.Sin(k * Mathf.PI);     // 0→1→0 (뜀·포물선)
float overshoot = Mathf.Sin(k * Mathf.PI * 1.5f) * (1f - k);  // 지나쳤다 잦아듦
```

**포물선을 앞쪽으로 치우치려면** (확 솟았다 천천히 떨어짐):
`Mathf.Sin(Mathf.Pow(k, 0.75f) * Mathf.PI)`

**튕기며 잦아드는 여운** (파르르):
`Mathf.Sin(k * Mathf.PI * n) * (1f - k)` — n이 클수록 여러 번 튄다

## 4단계 — 타격·이펙트 시점을 맞춘다

**타격 판정은 K2(오버슈트 정점) 직전에 넣는다.** 눈에 무기가 가장 빠르게 지나가는
그 순간이다. 도착한 뒤에 넣으면 "때리고 나서 피가 닳는" 어긋남이 생긴다.

이 프로젝트에서:
- 클립 저작 → **애니메이션 이벤트**를 그 프레임에 찍고 `PlayerGather.AnimImpact()` 호출
- 코드 → 본동작이 끝나는 지점에서 호출

**판정은 한 순간이 아니라 짧은 구간이어야 한다** (0.1~0.15초). 한 프레임만 검사하면
빠른 동작에서 상대가 그 프레임에만 범위 밖이면 그냥 빗나간다. 실제로 이 문제를 겪었다.

**이펙트 순서** — 동시에 터뜨리지 말고 시차를 준다:
1. K2 직전 — 타격 판정
2. K2 — 번쩍(작게) + 화면 흔들림
3. K2 + 0.05초 — 먼지·파편
4. K2 + 0.1초 — 피해 숫자

전부 같은 프레임에 나오면 뭉개져서 하나로 보인다.

## 5단계 — 살을 붙인다

3막 구조가 되고 나서만 손댄다. 순서를 바꾸면 밋밋한 동작에 장식만 붙는다.

**스쿼시 & 스트레치** — 부피를 유지하며 늘리고 누른다.
- 빠르게 움직일 때: 진행 방향으로 늘리고 옆으로 좁힌다
- 충돌·착지: 납작하게 눌렀다 되돌아온다
- 공식: 세로 `s` 배로 누르면 가로는 `1/√s` 배로 넓힌다

**시차 (Stagger)** — 여러 개가 동시에 움직이면 하나로 보인다. 개체마다 **0.05~0.1초씩**
어긋나게 출발시킨다. "퐁…퐁…퐁" 이 되면 성공, "퐁!" 하나로 들리면 실패다.

**히트스톱** — 강한 타격에서 0.03~0.06초만 시간을 멈춘다. 무게가 확 생긴다.
너무 길면 렉처럼 느껴진다.

**화면 흔들림** — 짧고 강하게. 길게 흔들면 멀미가 난다. `FollowCam.Shake(0.1~0.3)`

## 이 프로젝트의 제약

**클립은 정확히 1.00초로 만든다.** 공격 속도는 클립 배속으로 낸다 — 클립 길이를 바꾸면
공속을 조절할 때마다 다시 저작해야 한다.

**소유권을 지킨다.** 리그 본체(`HandRig`)와 무기 안쪽 모델은 코드가, `HandL`·`HandR`·`Bow`
는 애니메이션 클립이 갖는다. 클립에 무기 모델 키프레임을 넣으면 코드와 충돌해 떨린다.

**절차 모션 훅** — 코드로 캐릭터를 움직일 때 쓴다 (`BlobMotion`):
- `skillPitch` — 앞으로 넘어가는 각도 (구르기·던지기)
- `skillYaw` — 좌우 회전
- `skillHop` — 추가로 띄우는 높이
- `skillHoldFacing` — 그동안 마우스를 안 따라가게 잡기

`PetMotion` 은 **몸높이로 템포를 정한다** (작으면 촐랑, 크면 쿵). 새 모션을 넣을 때
절대 시간(초)으로 박으면 큰 놈과 작은 놈이 같은 박자로 움직여 어색해진다.
`tempo` 나 크기 보정을 통과시켜라.

**★스케일 함정** — 이 세계는 캐릭터 키가 0.42m다(`WorldScale.K` = 0.1).
**미터 단위 상수를 새로 쓸 때는 반드시 `* WorldScale.K` 를 곱한다.** 그리고 **"이 값의
기준은 어느 스케일인가"를 먼저 물어라.** 크기를 재는 *기준값*이 옛 스케일로 남아 있어
연쇄 오작동한 사례가 여러 번 있었다 (몸 크기 하한 1m, 모션 기준 몸높이 1.5m 등).

## 마무리 점검

동작을 만든 뒤 이 다섯 개를 확인한다. 하나라도 "아니오"면 그게 밋밋함의 원인이다.

1. **예비동작이 있나?** 반대 방향으로 먼저 움직이나
2. **본동작이 셋 중 가장 짧나?** 길면 느려 보인다
3. **목표를 지나쳤다 돌아오나?** (오버슈트)
4. **등속 구간이 없나?** Linear 는 기계처럼 보인다
5. **여러 개가 동시에 나오면 시차가 있나?**

그리고 마지막으로 — **유니티에서 눈으로 본다.** 숫자로 맞춘 모션은 반드시 어긋난다.
사용자에게 "너무 빠른가 / 뚝 끊기나 / 밋밋한가"를 물어보고 그 답으로 조정한다.
