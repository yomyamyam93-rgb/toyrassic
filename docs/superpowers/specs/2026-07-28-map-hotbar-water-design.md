# 지도 · 핫바/스킬바 · 물 · 구르기 — 설계

2026-07-28 · 사용자 요청 9건을 4묶음으로 정리했다.
묶음끼리는 서로 안 건드린다. 순서대로 하나씩 유니티에서 눈으로 확인하며 진행한다.

---

## A. 지도 — 회전 + 확대축소

**문제:** 맵이 6km 라 어디가 어딘지 못 찾겠다.

### A-1. 미니맵을 카메라 기준으로 돌린다

지금은 `RawImage.uvRect` 로 지형 텍스처를 잘라 보여준다. **uvRect 는 회전이 안 된다.**
구조를 바꾼다.

```
inner  (RectMask2D — 네모로 잘라냄)
 ├ mapContent            ← 카메라 yaw 만큼 역회전
 │   ├ RawImage          지형 그림 전체, 줌 배율만큼 확대
 │   └ 마커들            둥지·부화기 — 지도와 같이 돈다
 └ 내 화살표             마스크 바로 밑. 항상 정중앙, 안 돎
```

- `mapContent.localRotation = Euler(0, 0, cam.yaw)` → **카메라가 보는 쪽이 항상 지도 위쪽**
- `mapContent.anchoredPosition` = 내 위치 오프셋을 같은 각도로 회전시킨 값의 음수
  → 회전해도 내가 정중앙에 남는다
- 내 표시를 흰 점 → **삼각형 화살표**로. 회전 지도에서는 내가 어느 쪽을 보는지가 보여야
  의미가 있다. 각도 = `플레이어 yaw − 카메라 yaw`
- 마커(둥지·부화기)는 원이라 같이 돌아도 티가 안 난다 — 그대로 둔다

### A-2. 미니맵 휠 확대축소

- 휠 = `viewRadius` 조절. **150m ~ 2500m** (기본 700m). 곱셈 단계로 조절해 어느 배율에서도
  같은 손맛이 나게 한다
- 마커 크기는 배율과 무관하게 고정 — 축소했다고 둥지 표시가 점으로 사라지면 안 된다

### A-3. 전체 지도(M) 휠 확대축소

- 배율 **1x(섬 전체) ~ 8x**. 확대 시 중심은 내 위치
- **회전 안 시킨다.** 섬 전체를 볼 때는 북쪽 고정이 읽기 쉽다

### A-4. 휠 소유권 — 카메라 줌과 충돌

마우스 휠은 이미 `FollowCam` 이 카메라 줌으로 쓰고 있다. 그대로 두면 지도를 확대할 때
카메라도 같이 움직인다.

`MapUI.PointerOverMap` (static) 을 두고, `FollowCam` 이 `MenuUI.IsOpen` 을 보는 것과
**똑같은 방식**으로 참조해 커서가 지도 위면 카메라 줌을 끈다.
전체 지도가 열려 있는 동안은 무조건 끈다.

**확인 방법:** 유니티 실행 → 우클릭 드래그로 카메라를 돌린다. 미니맵이 같이 돈다.
미니맵 위에서 휠 → 지도만 확대되고 카메라는 가만히 있다. 지도 밖에서 휠 → 카메라 줌.

## B. 둥지 알 — 크게 + 흰 빛줄기

**문제:** 알이 작아서 안 보인다.

- 알 크기 `1.6 × 2.1 × 1.6` → **`2.4 × 3.2 × 2.4`** (1.5배)
- 위치 `y 1.6` → **`2.2`** — 커진 만큼 올려야 둥지에 묻히지 않는다
- 알 자리에서 **흰 빛줄기** — 원기둥, 높이 300m · 반경 0.6m,
  Unlit 반투명 흰색, 그림자·충돌 없음
- **알이 남아 있는 둥지 전부, 항상 보인다.** 알을 가져가면 빛줄기도 같이 사라진다
  (알 오브젝트의 자식으로 만들어 수명을 묶는다 — 따로 지우는 코드가 필요 없어진다)

**확인 방법:** 실행하면 멀리서도 흰 기둥이 여러 개 보인다. 둥지를 털어 알을 얻으면
그 기둥만 사라진다.

## C. 핫바 1~0 복구 · 스킬바 QER

### C-1. 아이템을 못 쓰게 된 원인

오늘 회사 작업(`eda3505`)에서 핫바가 **10칸 → 3칸**으로 줄었다.
자동 장착 순서가 `칼 → 활 → 도끼 → 곡괭이 → 새총 → 둥지` 라서 앞 3개가 차면
**곡괭이·새총·둥지는 칸에 못 들어간다.**

그리고 `PlayerBow.cs:862` 를 보면 **"사용" = 그 칸을 골라 손에 들고 좌클릭** 이다.
칸에 못 넣으니 손에 들 수가 없고, 그래서 쓸 수가 없었다.

### C-2. 핫바 10칸

- 칸 **10개** (`1 2 3 4 5 6 7 8 9 0`), 숫자키로 선택
- 칸이 저장하는 값을 `GearKind` → **아이템 ID(문자열)** 로 바꾼다.
  "뭐든 낄 수 있게" 하려면 이게 필요하다
- `SlotKind(i)` 는 `ItemDB.GearOf(id)` 로 계산해 돌려준다
  → **`Hotbar.SlotKind` 를 쓰는 다른 스크립트는 하나도 안 고쳐도 된다**
- **1·2·3 = 장비만.** 장비가 아닌 걸 끌어다 놓으면 튕겨내고 토스트로 알린다
- **4~0 = 뭐든.** 장비도 되고 아이템도 된다
- **QER 은 1·2·3 만 본다** (`SkillSystem.SlotGear`) — 지금 그대로
- 핫바 칸은 인벤토리를 **가리키는 바로가기**다. 수량은 인벤에서 읽어 칸에 표시하고,
  0이 되면 칸이 저절로 빈다. 아이템이 복제되지 않게 하는 유일한 방법이다
- 자동 장착: 칼·활·도끼를 1·2·3 에, 곡괭이·새총·둥지는 4번부터

### C-3. 스킬바

- 칸 4개: **`Q` `E` `R` `Space`**
- 칸에는 **큰 글자로 Q / E / R / Space 만** 쓴다.
  지금 칸 안에 있는 `1번 트리케라 ×10 · 흩뿌리기` 같은 긴 글자는 전부 툴팁으로 내린다
- 쓰면 칸이 어두워지고 **시계방향으로 차오르는 쿨타임**, 남은 초를 숫자로
- **툴팁** — 마우스를 올리면 칸 위에 뜬다. 4줄:

```
흩뿌리기                    ← 스킬 이름
부채꼴로 펫을 흩뿌린다       ← 설명 한 줄
트리케라톱스 × 10마리        ← 던질 펫·마릿수
재사용까지 7.2초             ← 남은 쿨타임 (0이면 "사용 가능")
누른 채 조준, 떼면 발사       ← 조작 안내
```

### C-4. 쿨타임이 안 도는 것

"쓰면 쿨타임 돌게 해달라" 는 요청은 **지금 쿨이 눈에 안 보인다**는 뜻이다.
코드상 쿨 계산(`PetCommand.CoolOf`)은 있으나 화면 표시가 제대로 안 도는 것으로 보인다.

**추측으로 고치지 않는다.** 구현할 때 `systematic-debugging` 절차로
먼저 재현시켜 놓고 원인을 잡는다.

**확인 방법:** 하단에 칸 10개가 보인다. 4번에 둥지를 넣고 `4` 를 누르면 손에 들리고
좌클릭으로 설치된다. 1번에 나뭇가지를 끌어다 놓으면 거부된다.
Q 를 쓰면 스킬칸이 차오르고 숫자가 줄어든다. 마우스를 올리면 툴팁 5줄이 뜬다.

## D. 물 · 구르기

### D-1. 원인 — `waterY = 40` 인데 실제 바다는 `y = 12`

`PlayerMove.cs:23` 은 물 높이를 **상수 40** 으로 박아 놓았다.
씬의 실제 바다 평면(`Ocean`, 7200×7200m)은 **y = 12** 에 있다.

즉 **높이 12~40m 사이의 땅 — 해안가 저지대 전부 — 이 코드상 "물속"** 이다.
바다보다 28m 높은 마른 땅인데 이속이 0.55배가 된다.

게다가 씬에는 **내륙 호수 3개**(y = 72.2 / 82.4 / 91, 각 ~460m)가 따로 있다.
물 높이가 곳마다 다르므로 **상수 하나로는 애초에 맞출 수가 없다.**

### D-2. `WaterBody.cs` — 물을 실측한다

- 씬을 손대지 않는다. **`KTWater` 셰이더를 쓰는 렌더러 = 물** 로 자동 인식한다
  (이름 규칙에 안 기댄다 — 이름은 바뀌지만 셰이더는 안 바뀐다)
- 각 물의 수면 높이(`renderer.bounds.max.y`)와 XZ 범위를 등록
- `WaterBody.SurfaceAt(위치)` → 그 지점을 덮는 물 중 가장 높은 수면, 없으면 없음
- 바다도 호수도 같은 규칙으로 처리된다

### D-3. 수심 3단계

`수심 = 수면 − 지면`

| 수심 | 상태 | 이동 |
|---|---|---|
| 0m (물 밖) | 걷기 | 100% |
| ~1.2m | 얕은 물 첨벙 | 수심에 비례해 100% → 55% 로 서서히 |
| 1.2m 초과 | **수영** | 수면에 떠서 `swimSpeed` (기본 이속의 50%) |

- 수영 중엔 `np.y = GroundAt(np)` 를 **안 쓴다.** 몸이 수면에 반쯤 잠긴 높이로 고정
  → 물속 지면을 뚫고 걷던 것이 사라진다
- 지금 속도 페널티는 **켜짐/꺼짐 두 값뿐**이라 경계에서 툭 끊긴다.
  수심 비례로 바꾸면 그 계단도 같이 없어진다

### D-4. 수영 모션

`BlobMotion` 에 `Swim` 모드를 추가한다. 리깅이 없으므로 절차 모션이다.
몸이 수면에 눌려 납작해지고, 좌우로 기우뚱거리며 나아간다.
`motion-authoring` 스킬 절차(3막 · 이징)를 따른다.

### D-5. 섬에서 너무 멀어지면 밀려난다

섬 중심에서 일정 거리를 넘으면 물살이 다시 안쪽으로 민다.
보이지 않는 벽 없이 경계를 만드는 방법이다.
수영 중에도 전투는 **전부 허용한다** (좌클릭·QER). 어색하면 그때 손본다.

### D-6. 물속 땅이 밝은 것

셰이더에 수심 처리는 **이미 있다** — 값이 문제다. `KTWater.mat` 현재값:

- `_DepthFade = 2` → **2m만 들어가면 이미 최대 수심**으로 쳐서 얕은 곳과 깊은 곳이 똑같다
- `_Tint = (0.87, 0.97, 1.0)` → 거의 **흰색**. 여기에 `_Bright 1.29`, `_Sat 1.42` 가 겹친다
- `_CenterDark = 0.575` 는 밝기를 42%까지만 낮춘다 — 어두운 심해가 안 나온다

고칠 것:

- `_DepthFade` **2 → 8m** — 얕은 물부터 깊은 물까지 그라데이션이 생긴다
- 셰이더에 **`_DeepColor`(깊은 물 색)** 추가. 수심에 따라 그 색으로 **섞는다**.
  지금처럼 밝기만 곱해 내리면 탁한 회색이 되지 뿌연 게 안 걷힌다

눈으로 보고 맞추는 값이다. 한 번 넣고 **사용자가 직접 보고 말로 알려주면** 조정한다.

### D-7. 구르기 후 딜레이

구르는 동안 `PlayerMove.cs:87` 이 `vel = Vector3.zero` 로 속도를 **죽인다.**
구르기가 끝나면 0에서 다시 가속하는데 `accel 34` / 최고속 `25.5` → **약 0.75초**.
그게 느껴지는 딜레이다.

고침: 구르기가 끝나는 순간 `vel` 을 **구른 방향 × 최고속도**로 채운다.
WASD 를 잡고 있으면 가속 구간 없이 그대로 달려나가고, 손을 뗐으면 기존 브레이크가
정상적으로 세운다.

**확인 방법:** 해안가 마른 땅에서 안 느려진다. 물에 들어가면 첨벙거리다 깊어지면
뜬 채로 헤엄친다. 물속 땅이 어둡다. 구르고 나서 바로 최고속으로 달린다.

## 순서

`A 지도` → `B 알` → `C 핫바/스킬바` → `D 물/구르기`

묶음마다 유니티에서 눈으로 확인하고 다음으로 넘어간다.
`D-6`(물색)과 `D-4`(수영 모션)은 값을 눈으로 맞춰야 하므로 사용자 확인이 두 번 필요하다.

## 안 하는 것

- 전체 지도 회전 (섬 전체는 북쪽 고정이 읽기 쉽다)
- 수영 중 스태미나·산소 (새 시스템이 필요하다. 경계는 물살로 만든다)
- 새 소모 아이템 (핫바가 받을 준비만 해두고, 실제 소모품은 생길 때 붙인다)
